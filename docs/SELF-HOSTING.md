# Свой сервер audio.lgbt

Нужны Linux x64, Docker Engine с Compose, домен с DNS A-записью на публичный IPv4 сервера и свободные TCP 443 / UDP 3478. Откройте эти порты в брандмауэре провайдера и ОС. При наличии AAAA-записи IPv6 тоже должен вести на этот сервер; иначе удалите ошибочную запись.

## Запуск

```sh
git clone https://github.com/aes-gcm/audio.lgbt.git
cd audio.lgbt
cp .env.example .env
```

Укажите в `.env` свой домен без `https://` и настоящий публичный IP:

```dotenv
AUDIO_DOMAIN=call.example.com
AUDIO_PUBLIC_IP=203.0.113.10
AUDIO_REQUIRE_AUTH=false
```

Адрес 203.0.113.10 — пример, замените его. Затем:

```sh
mkdir -p data
chmod 700 data
docker compose pull
docker compose up -d
docker compose logs -f --tail=100
```

Или соберите образ самостоятельно: `docker compose build --pull`, затем `docker compose up -d --pull never`.

Откройте `https://call.example.com`. Сертификат Let's Encrypt будет получен автоматически через TLS-ALPN-01 на 443. Сертификаты и аккаунты сохраняются в `data`; не удаляйте этот каталог при обновлении.

Compose использует Linux host networking: сервер объявляет реальные адреса ICE, а встроенный TURN обращается к SFU без дополнительного NAT Docker. Контейнер работает с read-only файловой системой и единственной добавленной capability NET_BIND_SERVICE. Доступ на запись есть только к `data` и временному каталогу. Это конфигурация для Linux-сервера; Docker Desktop на Windows не является проверенным способом публичного размещения.

Порт 443 одновременно обслуживает HTTPS, WebSocket и TURN-over-TLS. Обычный HTTP reverse proxy, TLS termination и Cloudflare orange-cloud перед ним не подходят: они ломают TURN и/или выдачу сертификата. Используйте прямую DNS-запись; продвинутый вариант — TCP passthrough с сохранением TLS. Порт 80 не нужен. TURN разрешает пересылку только к собственному SFU, а не к произвольным интернет-адресам.

## Создание комнат только после входа

Создайте один или несколько аккаунтов:

```sh
bash scripts/account.sh admin
bash scripts/account.sh alice
```

Скрипт скрыто запросит пароль и повтор. Пароль передаётся через stdin, не через аргументы процесса. Минимум 12 символов; для Unicode ограничение 72 байта. Каждый аккаунт имеет право создавать комнаты. Публичной регистрации нет.

Поставьте `AUDIO_REQUIRE_AUTH=true` в `.env` и примените:

```sh
docker compose up -d
```

Теперь «Создать звонок» сначала предложит логин и пароль. Организатор входит в комнату и отправляет приглашение. Гости подключаются без аккаунта. Если все вышли или сервер перезапустился, организатор должен открыть комнату снова; знание старой ссылки само по себе не даёт права создавать комнаты.

Управление аккаунтами:

```sh
docker compose run --rm --no-deps audio account -file /data/accounts.json -list
bash scripts/account.sh alice
docker compose run --rm --no-deps audio account -file /data/accounts.json -delete alice
```

Повторное добавление меняет пароль. Изменение пароля или удаление аккаунта сразу отменяет его сессии для новых подключений, но не обрывает уже начатые звонки. Сессии живут до 12 часов и сбрасываются при перезапуске. В файле только bcrypt-хеши; храните резервную копию `data` как закрытые данные. Одновременно команды изменения аккаунтов не запускайте.

При включённом ограничении отсутствие/повреждение файла или пустой список пользователей останавливает запуск — сервер не переходит сам в открытый режим. Режим по умолчанию открытый, как на основном audio.lgbt. Старый `-room-secret` оставлен для совместимости, но не может обойти `-require-auth`.

## Приложение Windows

Установите официальный клиент. На стартовом экране нажмите «Сервер: audio.lgbt», введите `https://call.example.com/` и нажмите «Подключить сервер». Адрес сохраняется после перезапуска. Для ограниченного сервера вход появится при создании комнаты. В этом же окне можно войти или выйти из аккаунта.

Приглашения и история проверяются по origin выбранного сервера. Клиент не отправляет сессию одного сервера другому. Сессия хранится только в памяти; пароль не сохраняется. Смена сервера доступна вне звонка. HTTP разрешён только для localhost при разработке; ошибки сертификата не игнорируются.

Обновления официального клиента приходят из GitHub aes-gcm/audio.lgbt-windows, независимо от выбранного сервера звонков. Самостоятельный сервер не получает права устанавливать код на компьютеры участников. Для собственной сборки клиента можно отключить официальные обновления через `-p:OfficialUpdates=false`.

## Обновление, резервные копии и диагностика

```sh
docker compose pull
docker compose up -d
curl -fsS https://call.example.com/healthz
docker compose logs --tail=100
```

Обновление перезапускает сервер и завершает активные звонки; выполняйте его, когда участники вышли. Для предсказуемого обновления вместо `latest` укажите тег SHA нужного коммита в compose. Для резервной копии сохраните `.env` и `data`; не публикуйте их в GitHub. `docker compose down` останавливает сервер, данные остаются.

Если сайт работает, а медиа нет: проверьте публичный IP, UDP 3478 и отсутствие HTTP-прокси перед 443. В звонке выберите «Только TLS», чтобы проверить встроенный relay. После настройки проверьте звонок с двух разных внешних сетей, а не только внутри своей LAN.

## Разработка без Docker

```sh
go build -o audio-server ./cmd/audio-server
./audio-server -dev -http 127.0.0.1:8080 -udp 3478
```

Откройте `http://localhost:8080`. Режим разработки не включает TLS/TURN и не предназначен для публикации наружу. Для production бинарник принимает `-domain`, `-public-ip`, `-cert-dir`, `-accounts`, `-require-auth`; `-help` показывает остальные параметры. Собственный сертификат задаётся парой `-tls-cert` / `-tls-key`.

## Отдельный Windows-клиент

Серверный репозиторий и Docker-образ не содержат исходники или установщик Windows. Готовый клиент скачивается с https://audio.lgbt/download; его исходники находятся в https://github.com/aes-gcm/audio.lgbt-windows. Выберите свой HTTPS URL кнопкой «Сервер» в приложении.
